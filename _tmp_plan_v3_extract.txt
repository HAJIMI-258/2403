0. 执行摘要
这是一份全新整理的实验规划书。它不延续上一版以“后续开发路线”为中心的写法，而是把 NOPS-OWR 当前最关键的问题重新定义为一个可实验验证、可逐层证伪、可复现实验的研究体系。核心目标不是证明系统“总体涨点”，而是证明系统是否真正具备开放世界流式识别中的三类能力：看见对象、维持身份、在长间隔后通过记忆召回旧连续体。
当前系统已经不是一个普通视觉识别原型。它已有 spike/event-like 编码、连续 objectness、support-region proposal、tracking、prototype memory、lineage、continuation、anchor、budget 和大量审计脚本。真正需要实验验证的是：这些结构是否组成了一个可靠的“知觉—身份—情景连续性记忆—语义概念记忆”闭环。
本规划书的中心判断是：后续实验必须从“最终分数评估”转向“机制级评估”。如果一个改动提高了 same-lineage，但压低 same-track-after-concept，它不是简单变好；如果一个改动提高了 same-prototype，但是靠压制 recovery path 得到，它可能是错误稳定；如果一个改动让 claim-builder 分数变好，但正确 continuity source 从未进入候选池，它没有修复根因。
因此，本文把实验体系重构为五层：感知层、身份层、概念层、连续性记忆层、记忆治理层。每一层都有独立事件族、指标、消融、负对照和失败归因规则。系统每一次更新，都必须回答“它到底修了哪一层，破坏了哪一层，是否只是制造了表面稳定”。
0.1 本规划书的核心结论
不要把 overall recall 当作主证据。NOPS-OWR 的主证据应该是事件级、层级化、可审计的机制证据。
当前第一组实验不应围绕 promotion 调参，而应围绕 continuity source visibility 展开。正确旧源没有进入 source pool 时，后续 ranking 与 attach 的一切讨论都是伪问题。
same-lineage、same-prototype、same-track 必须分开评估。三者分别代表概念重认、原型连续、个体身份连续，不能互相替代。
必须加入负对照。比如故意打乱 continuity owner、随机化 claim source、禁用 provenance，以证明系统不是靠偶然相似或阈值偏置在工作。
实验产物必须能回放。每个 hard event 都应有 source pool、claim ranking、attach state、promotion state 和 memory state 的完整 trace。
0.2 本文档与普通实验计划的区别
普通实验计划常见结构是：列 benchmark、列指标、跑 baseline、做 ablation。这个结构对闭集识别或普通 tracking 足够，但对 NOPS-OWR 不够。因为 NOPS-OWR 的失败往往不是单点错误，而是源于多层身份结构之间的错配：runtime owner 与 continuity owner 被混用，概念归属与身份接回被混用，temporary attach 与 semantic head promotion 被混用，prototype 实体与 lineage 主干被混用。
因此，本规划书以“机制断点”为基本实验对象。每个实验不是只问指标涨没涨，而是问：候选是否可见、来源是否被保留、claim 是否可解释、attach 是否独立于 promotion、记忆是否在 budget 压力下保留关键恢复入口。
1. 实验问题的重新定义
1.1 从“识别准确率”转向“持续识别能力”
本项目不应再被实验上定义为“识别模型准确率提升问题”。更准确的定义是：在无预训练、无离线数据、单遍流式输入、纯 SNN 风格约束下，系统能否通过自身经历形成对象、身份、概念与记忆，并在遮挡、漂移、重入、预算压力下保持可恢复性。
因此，实验对象不是单个预测结果，而是一个随时间演化的内部状态系统。一个成功系统至少要同时满足三类要求：第一，感知层形成对象支持区域；第二，身份层维持或恢复对象连续性；第三，记忆层保存并召回能够支撑旧身份恢复的 continuity source。
1.2 实验要验证的因果链
后续实验应围绕以下因果链展开，而不是围绕散乱指标展开：
1.   连续 objectness 与 support region 是否足以稳定形成对象候选；
2.   对象候选是否能在短时内绑定到正确 active identity；
3.   当短时 identity 断开时，lineage 是否仍能维持旧概念主干；
4.   当对象 long-gap re-entry 时，正确 continuity source 是否进入候选池；
5.   claim-builder 是否能在看见正确 source 后给出合理排序；
6.   temporary attach 是否能在不立即 promotion 的情况下恢复旧连续性；
7.   deferred promotion 是否能在持续证据充分时更新长期头节点；
8.   memory governance 是否能在预算压力下保留关键恢复 source。
1.3 哪些结果不能算强证据
为了避免误判，以下结果不能单独作为系统进步的强证据：
overall recall 上涨，但 source visibility 没有变化；
same-lineage 上涨，但 same-track-after-concept 下跌；
same-prototype 上涨，但 continuation access 下跌；
FP/frame 下降，但 recall 路径被 suppression 饿死；
head churn 下降，但 re-entry attach 被系统性阻断；
单个 hard case 成功，但没有 trace 证明正确 continuity source 进入并被使用。
2. 总体实验哲学：可证伪，而不是堆指标
NOPS-OWR 的实验体系必须具备可证伪性。也就是说，每个主张都要有对应的反例设计、负对照和失败判据。只做成功案例回放，或者只比较最佳配置的最终分数，都不足以证明系统实现了类脑式持续识别。
2.1 分层可证伪原则
每个实验都必须明确自己试图证伪哪一层假设。比如，若要证明 dual-owner 枚举有效，不能只看 same-track；必须先看正确 continuity owner 是否重新进入 source pool。若要证明 episodic bundle 有效，不能只看 same-lineage；必须看 long-gap 条件下 bundle access 与 attach 成功之间的关系。
2.2 最小改动原则
一次实验尽量只改变一个结构因素。比如阶段 A 中只开放 runtime owner + continuity owner 的双 source 枚举，先不要同时改 ranking、attach threshold、promotion gate 和 budget policy。否则，即使指标上涨，也无法判断原因。
2.3 对抗性负对照原则
所有看起来有效的新机制都必须经受负对照。比如，dual-owner 枚举若真的有效，则随机打乱 continuity owner 后应当显著破坏 long-gap recovery；episodic bundle 若真的有效，则禁用 temporal gap compatibility 后应当提高 false attach；deferred promotion 若真的有效，则 immediate promotion 应当带来更高 head churn 或 false promotion。
2.4 事件级配对比较原则
不要只比较两个系统的全局均值。对于 hard re-entry，最强证据是同一 event_id 在 baseline 与改动版本下的配对对比：source 是否从不可见变为可见，claim rank 是否从缺失变为进入 top-k，attach state 是否从 none 进入 temporary_attach，最终是否保持 same-lineage 或 same-track。

H8
自举约束假设
系统在 no-pretrain/no-offline-data/one-pass 约束下仍可形成可恢复内部概念。

4. 实验平台总架构
实验平台必须从“跑一次 runner，输出若干指标”升级为“事件账本 + 审计总线 + 指标引擎 + 产物存储 + 报告生成”的结构。否则系统越复杂，越难知道每次改动到底修了什么。

4.3 实验平台的最低要求
每个 benchmark 结果必须能追溯到 event_id，而不是只给 sequence-level 均值。
每个 event 必须能导出 source pool，且保留 runtime_owner 与 continuity_owner 的 provenance。
每个 attach 决策必须能导出 attach state transition。

8.1 E2：Dual-owner Visibility 实验细化

10. 统计与结果判读规范
即使实验多为 synthetic/controlled episodes，也必须采用严谨结果判读。尤其要避免只报告最佳 run 或只看全局均值。
10.1 事件级配对比较
所有关键机制实验都应采用 event-level paired comparison。对于每个 event_id，记录 baseline 与 variant 的层级结果，然后统计从失败到成功、从不可见到可见、从错误 attach 到正确 attach 的转换比例。
10.2 随机性与置信区间
如果 synthetic episode 含随机运动、干扰物、噪声或预算顺序，应至少固定多个 seeds，并报告 bootstrap confidence intervals。若数据量暂时较小，也应报告事件数、成功数和失败数，而不是只给小数。
10.3 结果判读优先级
1.   先看感知层是否足以支持后续模块；
2.   再看正确 continuity source 是否可见；
3.   再看 claim-builder 是否把正确 source 排进 top-k；
4.   再看 attach 是否发生且是否能跨帧存活；
5.   再看是否 promotion，以及 promotion 是否造成 head churn；
6.   最后看整体 U-Recall、PFR 或总体 recovery。
10.4 报告格式要求
每张结果表必须包含 raw numerator/denominator，不能只给小数。比如 same-track-after-concept = 9/17，而不是只写 0.529。这样能避免少量事件导致的假稳定。

结语：这份实验规划书的真正用途
这份文档的用途不是让项目看起来更大，而是让项目不再靠感觉推进。NOPS-OWR 的难点在于系统内部已经出现多层身份与记忆结构，单一指标无法判断真实进步。后续每个改动都必须被事件化、分层化、可回放、可证伪。
如果这套实验体系执行到位，后续开发会出现一个很关键的变化：你不再需要问“这次为什么没涨点”，而是能直接看到正确 continuity source 是没进候选、被过滤、排序低、attach 被挡、promotion 错误，还是被 budget/forgetting 误伤。到那时，系统才真正具备研究级可控性。
